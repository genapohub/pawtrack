## 1. 接口规范与数据字典

### 1.1 RESTful API 设计规范

| 项目 | 规范 |
|------|------|
| 基础路径 | `https://api.pawtrack.com/v1` |
| 认证方式 | JWT Bearer Token（Header: `Authorization: Bearer {token}`） |
| Token 刷新 | 双 Token 机制（access_token 2h + refresh_token 30d） |
| 响应格式 | `{ "code": 0, "msg": "success", "data": {...} }` |
| 错误码 | 详见 1.3 错误码表 |
| 分页参数 | `?page=1&page_size=20` |
| 时间格式 | ISO 8601（`2026-07-21T10:30:00+08:00`） |

## 2. 核心状态机

### 2.1 设备绑定状态机

```
[未绑定] --扫码/输SN--> [绑定中] --验证成功--> [已绑定]
                                                  |
                                      --解绑请求--> [解绑中] --确认--> [未绑定]
```

### 2.2 碰头流程状态机

```
[空闲] --发起碰头(距离>50m)--> [等待对方确认]
                                  |
                     +-------------+-------------+
                     |                          |
             对方拒绝/超时(5min)          对方确认
                     |                          |
              [空闲] <------------------ [碰头进行中]
                                          |
                                +---------+---------+
                                |                   |
                          距离<5m确认          超时(30min)
                                |                   |
                         [碰头成功]             [碰头超时]
                         各得100积分              无积分
```

### 2.3 订单支付状态机

```
[待支付] --用户支付--> [支付中] --支付成功回调--> [已支付]
                                          |
                              --支付失败回调--> [支付失败]
                                          |
                              --超时(30min)--> [已取消]
```

### 2.4 会员订阅状态机

```
[未订阅] --支付成功--> [生效中] --到期--> [已过期]
     ^                    |
     |         --续费支付成功--
     |                    |
     +---- [续费中] <------+
```

## 3. 异常流程处理

### 3.1 定位异常处理

| 异常场景 | 检测条件 | 处理方式 | 用户提示 |
|----------|----------|----------|----------|
| GPS信号弱 | 定位精度>50m | 显示"定位中..." + 使用上次有效位置 | "当前GPS信号较弱，位置可能有偏差" |
| 设备离线 | >30min无数据上报 | 显示离线状态 + 最后已知位置 | "设备已离线，请检查设备状态" |
| 定位数据异常 | 速度>200km/h | 丢弃该数据点 | 不提示，静默处理 |

### 3.2 报警异常处理

| 异常场景 | 处理方式 | 用户提示 |
|----------|----------|----------|
| 误报（用户标记） | 记录误报标签，用于优化算法 | "已记录为误报，将优化报警算法" |
| 报警风暴（1分钟内>10次） | 静默后续报警5分钟 | "检测到频繁报警，已暂时静音5分钟" |
| 围栏设置过小（<20m） | 拒绝设置，提示最小范围 | "围栏范围不能小于20米" |

### 3.3 支付异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 支付成功但回调丢失 | 用户手动刷新订单状态，触发补单查询 |
| 重复支付 | 自动退款至原支付渠道 |
| 订阅续费失败 | 3天后重试，连续3次失败转免费版 |

### 3.4 社交异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| 碰头距离作弊（GPS模拟） | 检测异常速度/位置跳变，标记异常账号 |
| 骚扰/恶意碰头 | 被举报后审核，封禁社交功能 |
| 积分异常获取 | 自动回滚异常积分，通知用户 |

## 5. 推送通知规范

### 5.1 通知类型与优先级

| 类型 | 优先级 | 渠道 | 触发条件 |
|------|--------|------|----------|
| 紧急报警 | 最高 | Push+短信+App内 | 猫咪离开围栏 |
| 安全报警 | 高 | Push+App内 | 狗狗离开围栏（已开启） |
| 设备状态 | 中 | Push+App内 | 低电量/离线/拆卸 |
| 社交提醒 | 中 | Push+App内 | 碰头请求/确认 |
| 营销活动 | 低 | App内+站内信 | 会员优惠/积分到期 |
| 系统通知 | 低 | App内 | 公告/Banner更新 |

## 6. 数据保留与隐私策略

### 6.1 数据保留期限

| 数据类型 | 保留期限 | 说明 |
|----------|----------|------|
| 用户账号 | 永久 | 用户主动注销后30天彻底删除 |
| 宠物档案 | 永久 | 同用户账号 |
| 定位数据 | 免费7天/会员永久 | 按会员状态动态清理 |
| 报警记录 | 180天 | 逾期自动归档 |
| 碰头记录 | 永久 | 用户可手动删除 |
| 订单记录 | 永久 | 财务合规要求 |
| 操作日志 | 180天 | 审计要求 |

### 6.2 隐私控制

| 控制项 | 选项 | 默认 |
|--------|------|------|
| 位置可见性 | 仅自己/好友可见/所有人 | 好友可见 |
| 附近宠物展示 | 开启/关闭 | 开启（狗狗）/ 关闭（猫咪） |
| 碰头匹配 | 参与/不参与 | 参与（狗狗）/ 不参与（猫咪） |
| 数据分享给第三方 | 允许/拒绝 | 拒绝 |

### 6.3 数据安全

- 位置数据传输：TLS 1.3 加密
- 位置数据存储：AES-256 加密
- 用户密码：bcrypt 加盐哈希（cost=12）
- Token：JWT HS256 签名
- 敏感操作：短信验证码二次确认

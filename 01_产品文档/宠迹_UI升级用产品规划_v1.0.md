## 1. 从现有系统提炼的业务规则与现状

**现状（本机核对 + 2026-11-15 状态文件 + README 诚实边界）：**

- 仓库分支文档口径为 `dev`，基线说明为管理后台与小程序 **本地 Mock 主路径可预览**。
- **硬件为方案阶段，未投产**：无真实样机，未与厂商联调。MQTT/BLE/OTA 停在方案，不是已接入设备。

## 3. 每个功能点的实现说明

### 3.1 登录与预览身份（主路径起点）

| 项 | 说明 |
|---|---|
| 规则 | 默认 Mock：允许本地预览进入，不调用真实微信、短信或 Apple 登录。界面必须能看出「本地预览 / 非验收」。关闭 Mock 对接本地后端时，失败按真实接口错误展示，仍不宣称已接入生产登录。 |
| 页面 | 小程序 login；后台 Login。 |
| 交互 | 选择预览进入或提交账号。未登录访问需登录的页面，回到登录。 |
| 空态 / 加载 / 失败 | 空：必填未填，按钮禁用或提示「请先输入」。加载：登录中不可重复提交。失败：预览关闭且后端未启动「无法连接服务，请确认后端已启动」；凭证错误单独文案；不要用「出错了」一言以蔽之。 |
| 本轮 | **做**。真实微信/短信 **不做**。 |

### 3.2 添加宠物与列表

| 项 | 说明 |
|---|---|
| 规则 | 必须选择猫或狗（影响后续默认围栏）。名称必填，品种按现有字段。猫默认围栏 100m 且离家报警开启；狗默认 300m、报警默认关。 |
| 页面 | pet-add、pet-list、home 上的入口。 |
| 交互 | 首页提供添加入口（历史原型为 FAB，可保留或按现页调整，但不丢失入口）。列表展示在家/户外等状态标签（狗）或宅家（猫），数据来自 Mock 或接口，须能区分无设备与有设备。 |
| 空态 / 加载 / 失败 | 空：「还没有宠物，先添加一只」。加载：列表骨架。失败：保存失败保留表单；加载失败可重试。 |
| 本轮 | **做**。 |

### 3.3 绑定与管理设备（主路径）

| 项 | 说明 |
|---|---|
| 规则 | 绑定方式规划为扫码或输入 SN。Mock 下可用示例 SN 走通「绑定成功」信息结构，但必须写明非真机配对。状态机：未绑定 / 绑定中 / 已绑定 / 解绑中。解绑二次确认。一台设备同时只属于一只宠物（若接口拒绝，展示原因）。固件升级在无真机时只保留入口与「当前为示意」或禁用 + 原因。 |
| 页面 | device-bind、device-manage、宠物详情中的设备信息。 |
| 交互 | 输入 SN 或模拟扫码（真实相机权限失败要可改用手输）。成功后展示设备在线与电量（Mock 值），并引导去看位置或设围栏。 |
| 空态 / 加载 / 失败 | 空：未绑定「还没有定位器，请绑定设备」。加载：绑定中，按钮禁用。失败：SN 无效「未找到该设备或激活码不正确」（即使是 Mock 也走这条信息结构）；已被绑定「该设备已绑定其他宠物」；网络失败可重试；解绑失败不清掉列表项。禁止把失败写成已经连上真硬件。 |
| 本轮 | **做**。真实激活码体系、MQTT 上报、厂商联调 **不做**。 |

### 3.4 查看位置与历史轨迹（主路径）

## 4. 本轮升级范围与不做清单

### 4.1 本轮要做

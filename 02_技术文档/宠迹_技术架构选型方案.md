## 2. 技术选型详细说明

### 2.1 前端技术选型

#### 用户端：微信小程序 — uni-app (Vue 3)（✅ 已落地）

> **2026-08-09 更新**：移动端由 React Native 方案调整为 **uni-app (Vue 3 + Vite)**，编译目标微信小程序（同时支持 H5）。
> 落地位置：`04_前端项目/miniapp/`（26 屏对应 PRD S1-S26，含 WebSocket 实时定位、微信登录）。

| 维度 | uni-app (Vue3) ✅ | React Native | Flutter |
|------|------------------|-------------|---------|
| 开发效率 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 微信生态 | ⭐⭐⭐⭐⭐（原生小程序） | ⭐⭐ | ⭐⭐ |
| 定位/地图 SDK | ⭐⭐⭐⭐⭐（微信内置） | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| 社区生态 | ⭐⭐⭐⭐⭐（国内） | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 热更新 | ✅ 微信平台原生支持 | ✅ CodePush | ❌ |

**调整理由**：
- MVP 目标为微信小程序，uni-app 一套代码编译小程序 + H5，开发效率最高
- 微信登录/支付/订阅消息原生支持，避免 RN 桥接复杂度
- 用户端无需上架 App Store，小程序审核周期短，符合 MVP 快速上线节奏
- 保留 H5 编译能力，Web 分享场景可复用

#### 后台管理系统：React + Ant Design Pro（✅ 已落地 `04_前端项目/admin/`）

### 2.4 实时定位数据推送方案

```
设备(GPS/BLE) → API上报/MQTT(规划) → 定位服务 → Redis(实时位置 GEO + Stream)
                                               ↓
                                     WebSocket Server → 小程序客户端

定位数据流（MVP 已落地）：
  1. 设备/模拟器每5-30秒上报坐标（POST /location/upload）
  2. 定位服务写入 Redis Stream（location:stream）+ Redis Geo（location:geo:nearby）
  3. 通过 Redis Pub/Sub → WebSocket 实时推送位置更新到订阅者
  4. 围栏检测（见 2.4.1）→ 触发报警服务 → 报警入库 + WS 推送
  5. MongoDB 轨迹落盘（消费者 V2 实现）
```

#### 2.4.1 围栏检测方案（PostGIS 服务端检测）

```
方案（MVP 已落地）：上报触发式检测 + Haversine 距离计算（纯 Python，无需 PostGIS）

1. 设备上报位置 → 定位服务写 Redis GEO + Stream → Pub/Sub 推送
2. 上报时触发围栏检测（alarms.py /fence-check）：
   - 查询设备绑定的宠物（fence_enabled=true）
   - 用 Haversine 公式计算 (设备位置, 围栏中心) 距离
   - 距离 > fence_radius → 越界 → 写入 alarms 表 → WS 推送报警
3. 猫/狗差异化：猫越界 → leave_fence_cat（高优先级），狗 → leave_fence
```

> **为什么用 Haversine 而不是 PostGIS？**
> MVP 无 Docker 环境（PostGIS 依赖 Docker 镜像），采用 DECIMAL(10,7) 存经纬度 + Python Haversine 计算。
> 精度足够（宠物围栏场景米级），零额外依赖。V2 引入 PostGIS/PostGIS 空间索引可平滑升级。
> 完整实现见《宠迹_围栏检测服务端实现.md》（已同步为 Haversine 版）。

### 5.6 Sprint 5 · V2.0 社交阶段（v0.5.0 · 2026-08-10）

- **社交规则模块** `app/social_rules.py`：碰头积分 100（MEET_POINTS）、最小距离 50m（MEET_MIN_DISTANCE）、每日限次 1（DAILY_MEET_LIMIT）、Haversine 工具函数（解循环导入）
- **碰头全链路**：发起（>50m 校验 + 每日限次）→ 确认 → 实时距离轮询（GET /social/meets/{id}/distance）→ <5m 到达 → 完成（双方各 +100 积分）
- **碰头超时**：lifespan 后台任务 `_meet_timeout_worker`，每 60 秒扫描 confirmed > 30min → failed
- **匹配度算法** `_calc_match_score`：距离 40 + 活跃度 30 + 品种基础 15，满分 100，nearby 按匹配度降序返回
- **后台碰头审核** `GET/PUT /admin/meets` / `PUT /admin/meets/{id}/audit`：异常自动标记（<5m / 24h≥3次），驳回自动扣回双方积分
- 前端 18 屏（含 meet-seeking S16 / meet-success S17 / S8 地图视图）
- 测试 32 passed · 碰头全链路 10 步冒烟通过

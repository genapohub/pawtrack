# 宠迹 PawTrack — 支付-订阅最终一致性方案

> 版本：V1.1 | 首次：2026-07-21 | 更新：2026-08-09  
> 解决：订单支付成功 → 订阅记录创建 → 设备服务生效 的事务一致性  
> 状态：✅ 已落地（event_outbox 表 + orders.py Outbox 写入；消费者投递 V2 接 RabbitMQ）

---

## 1. 问题描述

### 1.1 业务场景

```
用户支付成功 → 订单状态更新 → 订阅记录创建 → 设备服务生效
```

**风险点**：
- 订单支付成功，但订阅记录创建失败 → 用户付费后无法使用 Pro 功能（严重）
- 订阅记录创建成功，但设备服务未生效 → 用户投诉
- 网络抖动导致支付回调丢失 → 订单状态未更新

### 1.2 一致性要求

| 操作 | 一致性要求 | 说明 |
|------|-----------|------|
| 订单支付 → 订单状态更新 | **强一致** | 本地事务 |
| 订单状态更新 → 订阅记录创建 | **最终一致** | 消息队列 + 重试 |
| 订阅记录创建 → 设备服务生效 | **最终一致** | 订阅记录即生效 |

## 2. 方案设计：本地事务 + 消息队列

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                     支付平台（微信/支付宝）               │
│  支付成功 → POST /orders/callback/{channel}             │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│                    API 服务（订单回调处理）               │
│  1. 验证签名                                         │
│  2. 本地事务：                                       │
│     BEGIN;                                          │
│       UPDATE orders SET status='paid' WHERE order_no; │
│       INSERT INTO outbox (event_type, payload);       │  ← 本地消息表
│     COMMIT;                                          │
│  3. 发送消息到 RabbitMQ                               │
│     （从 outbox 表读取后发送，保证至少一次投递）          │
└──────────────────────┬──────────────────────────────────┘
                       │ RabbitMQ: order.paid
                       ▼
┌─────────────────────────────────────────────────────────┐
│               订阅服务（消费者）                         │
│  1. 消费 order.paid 消息                             │
│  2. 本地事务：                                       │
│     BEGIN;                                          │
│       INSERT INTO subscriptions (...);                │
│       DELETE FROM outbox WHERE msg_id = ?;           │
│     COMMIT;                                          │
│  3. 更新用户 member_level = 'pro'                    │
│  4. WebSocket 推送 "订阅生效" 通知                    │
└─────────────────────────────────────────────────────────┘
```

### 2.2 本地消息表（Outbox Pattern）

```sql
-- 本地消息表（与订单表在同一数据库，保证本地事务）
CREATE TABLE event_outbox (
    id BIGSERIAL PRIMARY KEY,
    event_type VARCHAR(50) NOT NULL,       -- order.paid / order.refunded
    payload JSONB NOT NULL,                 -- 消息内容
    status VARCHAR(20) DEFAULT 'pending',  -- pending / sent / failed
    retry_count INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW(),
    sent_at TIMESTAMP
);

CREATE INDEX idx_outbox_status ON event_outbox(status, created_at);
```

**原理**：将"更新订单状态"和"写入消息表"放在同一个数据库事务中，保证要么都成功，要么都失败。

## 3. 详细流程

### 3.1 支付回调处理（API 服务）

```python
async def handle_pay_callback(channel: str, callback_data: dict):
    """处理支付平台回调"""
    
    # 1. 验证签名（防止伪造）
    if not verify_signature(callback_data):
        raise HTTPException(400, "签名验证失败")
    
    order_no = callback_data['order_no']
    transaction_id = callback_data['transaction_id']
    paid_at = datetime.fromtimestamp(callback_data['paid_at'])
    
    async with pg_pool.acquire() as conn:
        async with conn.transaction():
            # 2. 查询订单（幂等性检查）
            order = await conn.fetchrow(
                "SELECT status FROM orders WHERE order_no = $1", order_no
            )
            if not order:
                raise HTTPException(404, "订单不存在")
            if order['status'] == 'paid':
                return {"code": "SUCCESS"}  # 已处理，直接返回
            
            # 3. 本地事务：更新订单 + 写入消息表
            await conn.execute(
                "UPDATE orders SET status='paid', paid_at=$1, transaction_id=$2 WHERE order_no=$3",
                paid_at, transaction_id, order_no
            )
            await conn.execute(
                "INSERT INTO event_outbox (event_type, payload) VALUES ($1, $2)",
                "order.paid",
                json.dumps({
                    "order_no": order_no,
                    "user_id": ...,  # 从订单表读取
                    "plan": ...,     # 从订单表读取
                    "amount": ...,
                    "paid_at": int(paid_at.timestamp())
                })
            )
        
        # 4. 事务提交后，异步发送消息到 RabbitMQ
        # （不在事务内，避免 RabbitMQ 故障导致事务回滚）
        asyncio.create_task(send_to_rabbitmq(
            queue='order.paid',
            message={'order_no': order_no, ...}
        ))
    
    return {"code": "SUCCESS"}
```

### 3.2 订阅服务消费（消费者）

```python
async def consume_order_paid():
    """消费 order.paid 消息，创建订阅记录"""
    connection = await aio_pika.connect_robust(RABBITMQ_URL)
    channel = await connection.channel()
    queue = await channel.declare_queue('order.paid', durable=True)
    
    async for message in queue:
        async with message.process():  # 自动 ack
            data = json.loads(message.body)
            order_no = data['order_no']
            user_id = data['user_id']
            plan = data['plan']
            
            async with pg_pool.acquire() as conn:
                async with conn.transaction():
                    # 幂等性检查：订阅记录是否已存在
                    existing = await conn.fetchval(
                        "SELECT id FROM subscriptions WHERE order_id = (SELECT id FROM orders WHERE order_no=$1)",
                        order_no
                    )
                    if existing:
                        continue  # 已处理，跳过
                    
                    # 计算订阅起止时间
                    now = datetime.now()
                    if plan == 'basic_month':
                        expire_at = now + timedelta(days=30)
                    elif plan == 'pro_year':
                        expire_at = now + timedelta(days=365)
                    
                    # 创建订阅记录
                    await conn.execute("""
                        INSERT INTO subscriptions (user_id, order_id, plan, status, started_at, expire_at)
                        SELECT u.id, o.id, $1, 'active', NOW(), $2
                        FROM users u
                        JOIN orders o ON o.order_no = $3
                        WHERE u.id = $4
                    """, plan, expire_at, order_no, user_id)
                    
                    # 更新用户会员等级
                    await conn.execute(
                        "UPDATE users SET member_level=$1, member_expire_at=$2 WHERE id=$3",
                        plan.split('_')[0], expire_at, user_id
                    )
            
            # 推送订阅生效通知
            await push_to_user(user_id, {
                "type": "subscription_activated",
                "plan": plan,
                "expire_at": int(expire_at.timestamp())
            })
```

## 4. 异常处理与重试

### 4.1 消费失败重试

```yaml
RabbitMQ 重试策略:
  max_retries: 3
  retry_delay: [5s, 30s, 300s]  # 指数退避
  dead_letter_queue: order.paid.dlx  # 死信队列（人工介入）
```

### 4.2 人工介入流程

```
死信队列消息 → 管理后台告警 → 运营人员查看
  │
  ├─ 原因：订阅记录创建失败（数据库故障）
  │   → 数据库恢复后，手动重发消息
  │
  ├─ 原因：用户不存在（数据异常）
  │   → 联系用户，退款处理
  │
  └─ 原因：重复消费（幂等性保护已处理）
      → 手动丢弃消息
```

### 4.3 定时补偿任务

```python
# 每 5 分钟执行一次，检查是否有"已支付但未创建订阅"的订单
async def compensate_order_subscription():
    async with pg_pool.acquire() as conn:
        orphan_orders = await conn.fetch("""
            SELECT o.order_no, o.user_id, o.type
            FROM orders o
            LEFT JOIN subscriptions s ON s.order_id = o.id
            WHERE o.status = 'paid'
              AND s.id IS NULL           -- 没有对应的订阅记录
              AND o.paid_at < NOW() - INTERVAL '5 minutes'
        """)
        
        for order in orphan_orders:
            logger.warning(f"发现孤儿订单: {order['order_no']}")
            # 重新发送消息到 RabbitMQ
            await send_to_rabbitmq('order.paid', {
                'order_no': order['order_no'],
                'user_id': order['user_id'],
                'compensate': True  # 标记补偿消息
            })
```

## 5. 幂等性设计

### 5.1 订单回调幂等

```sql
-- 支付平台可能重复回调，用 transaction_id 去重
CREATE UNIQUE INDEX idx_orders_transaction_id ON orders(transaction_id) WHERE transaction_id IS NOT NULL;
```

### 5.2 订阅创建幂等

```sql
-- 同一订单只能创建一个订阅记录
ALTER TABLE subscriptions ADD CONSTRAINT uk_sub_order UNIQUE (order_id);
```

### 5.3 消息消费幂等

```python
# 消费者记录已处理的消息 ID（Redis）
processed_key = f"msg:processed:{message_id}"
if await redis.exists(processed_key):
    return  # 已处理，跳过
await redis.setex(processed_key, 86400, "1")  # 24小时去重
```

## 6. 完整状态机

### 6.1 订单状态

```
created → pending → paid → refunded
                  ↓
                failed
```

### 6.2 订阅状态

```
active → expired
   ↓
cancelled
```

### 6.3 状态转换触发

| 转换 | 触发条件 | 一致性保证 |
|------|---------|-----------|
| `pending` → `paid` | 支付回调 | 本地事务 + Outbox |
| `paid` → 订阅 `active` | 消费 `order.paid` | 消息队列 + 重试 |
| `active` → `expired` | 定时任务（每天检查） | 本地事务 |
| `active` → `cancelled` | 用户取消 | 本地事务 |

### 2.4 定位轨迹表 `locations`（MongoDB）

> 注：定位轨迹数据量大，使用 MongoDB 存储，TTL 自动过期

```javascript
// MongoDB Collection: locations
{
  "_id": ObjectId("..."),
  "device_id": 12345,
  "pet_id": 67890,
  "lat": 31.2304,          // 纬度
  "lng": 121.4737,         // 经度
  "accuracy": 5.0,          // 精度（米）
  "altitude": 12.0,         // 海拔
  "speed": 0.5,             // 速度（m/s）
  "is_indoor": false,       // 是否室内
  "source": "gps",          // 定位来源：gps/wifi/ble
  "created_at": ISODate("2026-07-21T10:30:00Z")
}

// TTL索引（免费用户7天，会员永久）
db.locations.createIndex({ "created_at": 1 }, { expireAfterSeconds: 604800 })
```

> **会员永久轨迹**：Pro 用户轨迹同步写入 `locations_archive` 表（PostgreSQL），见 2.4.1

#### 2.4.1 定位轨迹归档表 `locations_archive`（PostgreSQL，会员专属）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGSERIAL | PK | 记录ID |
| device_id | BIGINT | FK→devices.id | 设备ID |
| pet_id | BIGINT | FK→pets.id | 宠物ID |
| location | GEOGRAPHY(Point, 4326) | NOT NULL | 坐标（WGS84） |
| accuracy | DECIMAL(5,2) | | 精度（米） |
| source | VARCHAR(20) | | 来源：gps/wifi/ble |
| created_at | TIMESTAMP | DEFAULT NOW() | 创建时间 |

```sql
-- 按月份分区（会员轨迹永久保留）
CREATE TABLE locations_archive (
  id BIGSERIAL,
  device_id BIGINT NOT NULL,
  pet_id BIGINT NOT NULL,
  location GEOGRAPHY(Point, 4326) NOT NULL,
  accuracy DECIMAL(5,2),
  source VARCHAR(20),
  created_at TIMESTAMP DEFAULT NOW()
) PARTITION BY RANGE (created_at);

CREATE INDEX idx_loc_archive_device_time 
  ON locations_archive (device_id, created_at DESC);
CREATE INDEX idx_loc_archive_location 
  ON locations_archive USING GIST (location);
```

## 3. Redis 数据结构设计

### 3.1 实时定位缓存

```
# 设备最新位置（实时）
Key: location:realtime:{device_id}
Value: { "lat": 31.2304, "lng": 121.4737, "ts": 1721532000 }
TTL: 300s

# 用户所有宠物实时位置（批量查询）
Key: location:user:{user_id}
Value: Hash { pet_id: "{lat,lng,ts}" }

# 附近宠物地理索引（Redis GEO）
Key: location:geo:nearby
ZADD: { device_id: [lng, lat] }
```

### 3.2 会话与Token

```
# 用户登录Token
Key: auth:token:{user_id}
Value: { "access_token": "...", "refresh_token": "..." }
TTL: 7200s (access_token过期时间)

# 设备在线状态
Key: device:online:{device_id}
Value: 1
TTL: 300s（设备每30秒上报一次心跳）
```

### 3.3 限流控制

```
# API限流（用户维度）
Key: ratelimit:user:{user_id}:{api_path}
Value: 计数器
TTL: 60s
```

## 4. 分库分表策略

### 4.1 定位数据（MongoDB 自动分片）

- **分片键**：`device_id + created_at`
- **分片策略**：按时间范围自动分片（每月一个chunk）
- **TTL策略**：免费用户7天自动删除，会员永久保留

### 4.2 报警记录（PostgreSQL 分区表）

```sql
-- 按月份分区
CREATE TABLE alarms (
  id BIGSERIAL,
  pet_id BIGINT,
  ...
  created_at TIMESTAMP
) PARTITION BY RANGE (created_at);

CREATE TABLE alarms_2026_07 PARTITION OF alarms
  FOR VALUES FROM ('2026-07-01') TO ('2026-08-01');
```

### 4.3 订单数据（不分区）

- 订单总量预计：10万用户 × 平均2单 = 20万单/年
- 单表可支撑，无需分区

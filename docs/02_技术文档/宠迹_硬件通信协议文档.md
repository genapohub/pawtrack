## 1. 通信架构总览

### 1.1 整体通信拓扑

```
┌─────────────────────────────────────────────────────────┐
│                        云端                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────────┐ │
│  │ 定位服务   │  │ 设备服务  │  │ 报警服务  │  │ OTA服务 │ │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └───┬────┘ │
│       │             │              │             │       │
│  ┌────▼─────────────▼──────────────▼─────────────▼──┐  │
│  │              MQTT Broker (EMQX)                   │  │
│  └────────────────────┬──────────────────────────────┘  │
│                       │ MQTT/TLS:8883                     │
│  ┌────────────────────▼──────────────────────────────┐  │
│  │              API Gateway (Nginx + Kong)            │  │
│  └───┬──────────────┬──────────────┬─────────────────┘  │
│      │ HTTP/TLS:443  │ HTTPS        │ WebSocket/WSS      │
│      │  (设备管理)    │ (App/后台)    │ (实时推送)         │
└──────┼──────────────┼──────────────┼──────────────────────┘
       │              │              │
┌──────▼──────┐ ┌─────▼──────┐ ┌────▼──────┐
│  狗狗版设备   │ │ 猫咪版设备  │ │  App客户端  │
│  GPS+4G+WiFi│ │ BLE+WiFi   │ │  iOS/Android│
│  MQTT→EMQX  │ │ MQTT→EMQX  │ │ WebSocket← │
│  BLE↔App    │ │ BLE↔App    │ │  HTTP↔API  │
└─────────────┘ └────────────┘ └────────────┘
```

### 1.2 通信链路汇总

| 链路 | 协议 | 传输层 | 方向 | 用途 |
|------|------|--------|------|------|
| 设备→云端 | MQTT 5.0 | TCP/TLS:8883 | 上行 | 定位上报、状态心跳 |
| 云端→设备 | MQTT 5.0 | TCP/TLS:8883 | 下行 | 配置下发、固件升级指令 |
| 设备↔App | BLE 5.2 | BLE GATT | 双向 | 近场配对、参数配置、WiFi配网 |
| 云端→App | WebSocket | WSS | 下行 | 实时位置推送、报警推送 |
| App→云端 | HTTPS | TLS:443 | 上行 | REST API、设备注册 |

### 1.3 协议选型理由

| 方案 | 选型 | 理由 |
|------|------|------|
| 设备→云端 | **MQTT 5.0** | 轻量级、支持QoS、双向通信、低功耗、持续连接 |
| 近场通信 | **BLE 5.2** | 低功耗、兼容所有智能手机、无需蜂窝网络 |
| 实时推送 | **WebSocket** | 全双工、低延迟、App原生支持 |
| 配置管理 | **HTTPS REST** | 简单、可靠、兼容性好 |

## 2. MQTT 协议规范

### 2.1 MQTT Broker 配置

| 参数 | 值 | 说明 |
|------|----|------|
| Broker | EMQX 5.x | 开源 MQTT Broker，支持集群 |
| 端口 | 8883（TLS）/ 1883（内网） | 外网强制 TLS |
| 协议版本 | MQTT 5.0 | 支持 Session Expiry、User Properties |
| max_packet_size | 256KB | 单包最大尺寸（固件升级块） |
| keepalive | 60s | 心跳间隔 |
| session_expiry | 86400s | 离线消息保留24小时 |

### 2.2 Topic 树结构

```
pawtrack/
├── device/
│   ├── {sn}/location     ── 定位数据上报（上行，QoS 1）
│   ├── {sn}/status       ── 设备状态上报（上行，QoS 0）
│   ├── {sn}/alarm        ── 设备侧报警（上行，QoS 1）
│   ├── {sn}/config       ── 设备配置下发（下行，QoS 1）
│   ├── {sn}/ota          ── OTA升级指令（下行，QoS 1）
│   └── {sn}/ota/progress ── OTA升级进度（上行，QoS 0）
├── app/
│   └── {sn}/directive    ── App→设备指令代理（下行，QoS 1）
└── backend/
    └── internal          ── 服务间 Topic（内网使用）
```

**Topic 命名规范**：
- 使用层级结构，`/` 分隔
- 禁止通配符 `+` / `#` 在发布端使用（仅订阅端可用）
- Topic 名称中 `{sn}` 为小写字母设备序列号

### 2.3 QoS（服务质量）等级

| Topic | QoS | 说明 |
|-------|-----|------|
| `device/{sn}/location` | **QoS 1** | 至少送达一次。设备缓存最近一条，收到 Broker PUBACK 后清除 |
| `device/{sn}/status` | **QoS 0** | 最多送达一次。心跳状态，丢包不影响功能 |
| `device/{sn}/alarm` | **QoS 1** | 至少送达一次。报警必须送达 |
| `device/{sn}/config` | **QoS 1** | 至少送达一次。配置变更必须生效 |
| `device/{sn}/ota` | **QoS 1** | 至少送达一次。升级指令必须收到 |
| `device/{sn}/ota/progress` | **QoS 0** | 最多送达一次。进度展示，少量丢包可接受 |

### 2.4 设备鉴权

#### 2.4.1 连接认证（JWT-based）

```json
// 设备连接 MQTT Broker 时携带的 Credentials
{
  "username": "{sn}",
  "password": "{jwt_token}"
}

// JWT Claims
{
  "iss": "pawtrack",
  "sub": "{sn}",
  "iat": 1721532000,
  "exp": 1721532600,
  "hw_type": "cat | dog",
  "fw_version": "1.0.0"
}
```

- JWT 有效期：**10分钟**，到期后断开连接，设备需重新获取 Token
- Token 获取方式：设备首次注册或 Token 过期时，通过 **HTTPS 调用设备注册接口**获取
- HS256 签名，密钥由设备管理服务持有

#### 2.4.2 ACL（访问控制列表）

```
# EMQX ACL 规则
Allow: device/{sn}/location    (publish)  ONLY if client.username == {sn}
Allow: device/{sn}/status      (publish)  ONLY if client.username == {sn}
Allow: device/{sn}/alarm       (publish)  ONLY if client.username == {sn}
Allow: device/{sn}/config      (subscribe) ONLY if client.username == {sn}
Allow: device/{sn}/ota         (subscribe) ONLY if client.username == {sn}
Deny:  all                     (all)       (default)
```

**原理**：设备只能向自己的 Topic 发布消息，只能订阅下发给自己的 Topic，无法监听其他设备。

### 2.5 设备首次注册流程

```
设备上电
  │
  ├─ 首次开机？──────────────────┐
  │                              │
  ├─ BLE 广播（60s）              │
  │     │                        │
  │     ▼                        │
  │ App 扫描到设备                │ 设备已有 Token
  │     │                        │     │
  │     ▼                        │     ▼
  │ 通过 BLE 获取设备 SN           │ MQTT 连接 Broker
  │     │                        │     │
  │     ▼                        │     ▼
  │ App 调用 POST /api/v1/devices │ 正常数据上报
  │ 注册设备→返回 JWT+MQTT地址     │
  │     │                        │
  │     ▼                        │
  │ 通过 BLE 写入 JWT+MQTT配置     │
  │     │                        │
  │     ▼                        │
  │ 设备 MQTT 连接 Broker ────────┘
```

## 3. 数据包格式

### 3.1 定位数据上报（`device/{sn}/location`）

**Payload**：JSON/Protocol Buffers（二进制版）

```json
// JSON 格式
{
  "lat": 31.23041234,
  "lng": 121.47371234,
  "accuracy": 5.0,            // 定位精度（米）
  "altitude": 12.0,           // 海拔（米）
  "speed": 0.5,               // 速度（m/s）
  "bearing": 180.0,           // 方向角（度）
  "source": "gps",            // 定位来源：gps / wifi / ble / lbs
  "battery": 85,              // 当前电量 0-100
  "is_indoor": false,         // 是否室内
  "charging": false,           // 是否充电中
  "ts": 1721532000,           // 设备端时间戳（Unix秒）
  "seq": 1024                 // 序列号（去重用）
}
```

**狗狗版 GPS+4G**：
| 字段 | 说明 |
|------|------|
| 上报频率 | 户外GPS模式：5-30秒可配置，默认10秒 |
| | 室内WiFi模式：60秒 |
| | 静止休眠模式：300秒 |
| source | 默认 `gps`，室内切换 `wifi`，BLE辅助 `ble` |

**猫咪版 BLE+WiFi**：
| 字段 | 说明 |
|------|------|
| 上报频率 | 已连接WiFi：30秒 |
| | BLE中继模式：60秒 |
| | 离线模式：不上报（触发离线报警） |
| source | 默认 `wifi`（WiFi指纹定位），BLE中继 `ble` |

### 3.2 设备状态上报（`device/{sn}/status`）

```json
{
  "battery": 85,              // 电量 0-100
  "charging": false,          // 是否充电
  "rssi": -65,                // 信号强度 (dBm)
  "ble_state": "idle",        // BLE状态：idle / pairing / connected
  "wifi_state": "connected",  // WiFi状态：disconnected / connecting / connected
  "sim_signal": 0,            // 4G信号强度（仅狗狗版，0-5）
  "fw_version": "1.2.3",      // 当前固件版本
  "uptime": 86400,            // 开机时长（秒）
  "memory_free": 51200,       // 剩余内存（KB）
  "ts": 1721532000
}
```

**上报频率**：每 **60秒** 一次（无论连接状态）

### 3.3 设备侧报警（`device/{sn}/alarm`）

```json
{
  "type": "low_battery",      // low_battery / offline_warning / tamper_detected / fall_detected
  "severity": "medium",       // high / medium / low
  "lat": 31.2304,             // 报警位置（可选）
  "lng": 121.4737,
  "battery": 15,              // 触发时的电量
  "ts": 1721532000
}
```

| 报警类型 | 触发条件 | 级别 | 说明 |
|----------|---------|------|------|
| `low_battery` | 电量 < 20% | medium | 仅上报一次，充满重置 |
| `low_battery_critical` | 电量 < 10% | high | 每10分钟重复上报 |
| `offline_warning` | 网络断开 > 30分钟 | medium | 每次上线重置计数器 |
| `tamper_detected` | 设备被拆卸 | high | 触发即上报（需电容检测） |
| `fall_detected` | 加速度计检测到撞击 | medium | 仅狗狗版（户外活动） |

### 3.4 云端配置下发（`device/{sn}/config`）

**服务端下发**：
```json
{
  "seq": 1,                   // 配置序列号（去重、版本控制）
  "configs": {
    "location_interval": 10,   // 定位上报间隔（秒）
    "status_interval": 60,     // 状态上报间隔（秒）
    "fence_enabled": true,     // 围栏检测开关
    "fence_radius": 100,       // 围栏半径（米）
    "fence_center_lat": 31.2304,
    "fence_center_lng": 121.4737,
    "ble_beacon_interval": 5,  // BLE广播间隔（秒）
    "wifi_scan_interval": 60,  // WiFi扫描间隔（秒）
    "alarm_enabled": true,     // 报警开关
    "timezone": "Asia/Shanghai" // 时区
  },
  "ts": 1721532000
}
```

**设备回复**：
```json
{
  "seq": 1,
  "status": "applied",        // applied / rejected / failed
  "error": null,
  "ts": 1721532005
}
```

### 3.5 固件 OTA 升级（`device/{sn}/ota`）

```
服务端 → 设备：升级指令
{
  "type": "start",
  "version": "1.3.0",
  "url": "https://oss.pawtrack.app/firmware/dog-v1.3.0.bin",
  "md5": "a1b2c3d4e5f6...",
  "size": 524288,             // 固件大小（字节）
  "chunk_size": 4096,         // 建议分块大小
  "force": false              // 是否强制升级
}

设备 → 服务端：接受/拒绝
{
  "type": "accept" | "reject",
  "version": "1.3.0",
  "reason": null | "battery_low" | "charging" | "cancel"
}

// 接受后，设备通过 HTTPS 分块下载固件
// 下载完成 → 校验 MD5 → 写入 Flash → 重启

设备 → 服务端：进度上报（每个分块）
{
  "type": "progress",
  "progress": 50,              // 0-100
  "speed": 102400,             // 下载速度（byte/s）
  "eta": 30                    // 剩余时间（秒）
}
```

**OTA 安全规则**：
1. 固件包必须使用 RSA-2048 签名
2. 设备校验签名后才写入 Flash
3. 升级失败自动回滚到上一版本
4. 电量 < 30% 拒绝升级（除非 `force: true`）
5. 非充电状态拒绝升级大版本

## 4. BLE 近场通信协议

### 4.1 BLE GATT Service 定义

| Service UUID | 名称 | 说明 |
|-------------|------|------|
| `0xFFE0` | Device Info | 设备基本信息 |
| `0xFFE1` | Configuration | 设备参数配置 |
| `0xFFE2` | Real-time Data | 实时数据传输 |

### 4.2 Characteristics

#### 4.2.1 Device Info Service (`0xFFE0`)

| Characteristic UUID | 属性 | 说明 | 格式 |
|--------------------|------|------|------|
| `0xFFE1` | Read | 设备序列号 SN | String, 16字节 |
| `0xFFE2` | Read | 固件版本 | String, 8字节 |
| `0xFFE3` | Read | 硬件类型 (cat/dog) | String, 3字节 |
| `0xFFE4` | Read/Notify | 电池电量 (0-100) | uint8 |

#### 4.2.2 Configuration Service (`0xFFE1`)

| Characteristic UUID | 属性 | 说明 | 格式 |
|--------------------|------|------|------|
| `0xFFE1` | Write | WiFi SSID | String, 32字节 |
| `0xFFE2` | Write | WiFi Password | String, 64字节 |
| `0xFFE3` | Write | MQTT JWT Token | String, 256字节 |
| `0xFFE4` | Write | MQTT Broker URL | String, 128字节 |
| `0xFFE5` | Write | 围栏配置 | JSON, 256字节 |
| `0xFFE6` | Write/Notify | 配对确认 | uint8 (0/1) |

#### 4.2.3 Real-time Data Service (`0xFFE2`)

| Characteristic UUID | 属性 | 说明 | 格式 |
|--------------------|------|------|------|
| `0xFFE1` | Notify | 实时定位数据推送 | JSON, 128字节 |
| `0xFFE2` | Write | 寻找设备指令 | uint8 (0/1) |
| `0xFFE3` | Notify | 设备状态变更通知 | JSON, 64字节 |

### 4.3 BLE 配对流程

```
1. 设备开机 → BLE 广播（广播间隔 5s，持续 60s 后进入低功耗模式）
2. App 扫描 → 发现设备（广播包包含 SN 和硬件类型）
3. App 发起连接
4. 设备发送配对确认 Notification (0xFFE6 → 1)
5. App 写入 WiFi/MQTT 配置到 Configuration Service
6. 设备收到配置 → 连接 WiFi / 连接 MQTT Broker
7. 设备发送配对成功 Notification (0xFFE6 → 2)
8. App 断开 BLE 连接
9. 设备进入正常工作模式
```

### 4.4 BLE 广播包格式

```
[AD Type]  [Data]
0x01       Flags: LE General Discoverable
0x02       Incomplete List of 128-bit Service UUIDs
0xFF       Manufacturer Specific Data:
           - Company ID: 0xXXXX (宠迹自定义)
           - SN: 16 bytes ASCII
           - HW Type: 0x00=cat, 0x01=dog
           - Battery: 1 byte (0-100)
           - State: 0x00=待配对, 0x01=已配置, 0x02=已连接
```

## 5. 设备状态机

### 5.1 完整状态定义

```
                ┌───────────┐
                │ 出厂模式    │
                └─────┬─────┘
                      │ 首次开机
                ┌─────▼─────┐
         ┌─────│ 待配对模式   │ ←────┐
         │     └──────┬──────┘      │
         │            │ BLE配网完成   │
         │     ┌──────▼──────┐      │
         │     │ 连接中模式    │      │
         │     └──────┬──────┘      │
         │            │ 连接成功     │ 配置擦除
         │     ┌──────▼──────┐      │
         │     │ 正常工作模式  ├──────┘
         │     └──────┬──────┘
         │            │
         │     ┌──────▼──────┐
         │     │ 休眠模式     │
         │     └──────┬──────┘
         │            │ 定时唤醒/外部触发
         └────────────┘
```

### 5.2 状态切换条件

| 当前状态 | 触发事件 | 下一状态 | 说明 |
|---------|---------|---------|------|
| 出厂模式 | 首次上电 | 待配对模式 | 设备自动进入 BLE 广播 |
| 待配对模式 | BLE 配网成功 | 连接中 | App 写入 WiFi/MQTT 配置 |
| 连接中 | MQTT CONNACK 成功 | 正常工作 | 开始数据上报 |
| 连接中 | MQTT 连接失败 | 待配对模式 | 尝试 3 次后回退 |
| 正常工作 | 网络断开 > 30min | 待配对模式 | 触发离线报警 |
| 正常工作 | 静止 > 5min | 休眠模式 | 省电策略 |
| 正常工作 | 电量 < 5% | 休眠模式 | 仅保留 BLE 广播 |
| 休眠模式 | 加速度计检测到移动 | 连接中 | 自动恢复连接 |
| 休眠模式 | 定时唤醒（5min一次） | 连接中 | 检查是否有未送达消息 |

## 6. 错误码与异常处理

### 6.1 MQTT 通信错误码

| 错误码 | 说明 | 设备端处理 |
|--------|------|-----------|
| 0x01 | JWT 过期/无效 | 通过 BLE 请求新 Token |
| 0x02 | Topic 无权限 | 停止该 Topic 发布，上报日志 |
| 0x03 | 报文格式错误 | 丢弃报文，下次重试 |
| 0x04 | 服务器不可用 | 指数退避重试（1s→2s→4s→8s→30s max） |

### 6.2 设备端异常处理

```yaml
网络断开:
  - 缓存在线数据（FIFO，最多保留 1000 条）
  - 恢复连接后先恢复未确认的 QoS 1 消息
  - 3 分钟内重连失败 → 进入待配对模式

电量耗尽:
  - 保存最后位置到 Flash（断电不丢失）
  - 下次上电后优先上报存储的位置

固件升级失败:
  - 自动回滚到上一版本
  - 记录失败原因到 Flash
  - 下次上报状态时附带失败日志
```

## 7. 安全设计

### 7.1 通信安全

| 维度 | 方案 | 说明 |
|------|------|------|
| 传输加密 | TLS 1.3 | MQTT:8883 + HTTPS:443 |
| 设备证书 | 预置 CA 证书 | 出厂烧录，用于验证服务器身份 |
| 双向认证 | 可选 | V2 开启 mTLS |
| 消息加密 | Payload 可选 AES-256 | 位置数据敏感场景 |

### 7.2 数据安全

```yaml
数据上传:
  - 位置数据在设备端不做持久化
  - MQTT Payload 使用 TLS 传输加密
  - 云端存储使用 AES-256 加密

防篡改:
  - 固件包 RSA-2048 签名
  - 固件版本号递增，禁止降级
  - 配置下发带 seq 号防重放

防仿冒:
  - 每台设备预置唯一 SN + 密钥
  - JWT Token 10 分钟过期
  - 设备 MAC 地址与 SN 绑定
```

## 8. 附录：设备规格与资源约束

### 8.1 猫咪版 BLE+WiFi

| 参数 | 值 | 说明 |
|------|----|------|
